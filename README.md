# Baseline RAG: этап 1 — загрузка прикладного корпуса

На первом этапе подготовлена база знаний для будущего RAG-ассистента по услугам
DMV. Вместо восьми коротких карточек товаров теперь используется домен DMV из
IBM MultiDoc2Dial.

Код пока не строит эмбеддинги и не вызывает LLM. Его задача — гарантированно
получить чистые документы и эталонные вопросы для следующих этапов.

## Что находится в проекте

- 149 полноценных документов DMV;
- около 129 тысяч слов;
- 6525 обучающих пар «вопрос — ответ»;
- 1132 validation-пары;
- 1094 test-пары;
- эталонные ответы, правильные документы и конкретные фрагменты для проверки;
- загрузчик с нормализацией текста и диагностикой;
- воспроизводимый импорт из официального архива;
- автоматические тесты ошибок и структуры данных.

## Пайплайн первого этапа

```text
Официальный ZIP MultiDoc2Dial
        ↓
Извлечение домена DMV
        ↓
149 документов + вопросы и эталонные ссылки
        ↓
Проверка и нормализация текста
        ↓

```

## Основной запуск

Требуется Python 3.10 или новее. Внешние библиотеки не нужны.

```bash
python3 load_documents.py
```

Загрузчик:

1. читает 149 документов из `data/raw/multidoc2dial/dmv_documents.jsonl`;
2. проверяет обязательные поля и уникальность `document_id`;
3. проверяет UTF-8 и валидность JSON;
4. нормализует Unicode, пробелы и переносы;
5. считает документы, символы, слова и абзацы;
6. сохраняет подготовленный корпус в `data/prepared/dmv_documents.jsonl`.

## Повторный импорт официальных данных

Скрипт сам скачает архив, если его ещё нет:

```bash
python3 scripts/import_multidoc2dial.py
```

Можно передать уже скачанный архив:

```bash
python3 scripts/import_multidoc2dial.py \
  --archive /path/to/multidoc2dial.zip
```

## Формат документа

Каждая строка подготовленного JSONL содержит:

- `document_id` — стабильный идентификатор;
- `title` — название страницы DMV;
- `domain` — предметная область;
- `text` — очищенный полный текст;
- `metadata.spans` — размеченные фрагменты документа;
- `stats` — число символов, слов и абзацев.

## Формат контрольного вопроса

В файлах `dmv_questions_*.jsonl` для каждого вопроса сохранены:

- текст вопроса;
- история диалога;
- эталонный ответ оператора;
- идентификаторы правильных документов;
- точные фрагменты, на которых основан ответ.

Благодаря этому на следующих этапах можно будет посчитать `Recall@k`: попал ли
правильный документ в результаты поиска.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Проверяются:

- обычный UTF-8 файл;
- пустой файл;
- отсутствующий путь;
- неправильная кодировка;
- повреждённый JSON;
- повторяющиеся идентификаторы документов;
- сохранение метаданных и размеченных фрагментов;
- связь вопроса с ответом и эталонными документами;
- совместимость со старым текстовым примером.
